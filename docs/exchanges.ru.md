# Переключение торговли между биржами — Rawanga Trading Desk

> Этот документ объясняет, как сосуществуют два торговых бэкенда (BingX и
> Hyperliquid), как безопасно переключаться между ними и что происходит с
> позициями при переключении.
> Есть на трёх языках: `exchanges.en.md`, `exchanges.es.md`, `exchanges.ru.md`.

---

## 0. Главное правило

**В каждый момент активна ровно ОДНА биржа.**

Приложение всегда работает через один бэкенд. Режима «торговать на обеих» нет,
и это сделано намеренно: две биржи — это два баланса, два набора позиций и два
источника истины для одного торгового решения.

---

## 1. Чем бэкенды различаются

Это не вариации одного и того же — протоколы несовместимы, поэтому драйверов
два отдельных, а не один с переключателем внутри.

| | BingX (`exchange.py`) | Hyperliquid (`exchange_hl.py`) |
|---|---|---|
| Подпись | HMAC-SHA256 | EIP-712 + msgpack |
| Креды | API key + secret key | приватный ключ агента (API-кошелёк) + адрес мастер-аккаунта |
| Режим позиций | хедж (LONG/SHORT) | только one-way |
| Тип ордера | MARKET | агрессивный IOC-лимит (MARKET у HL нет) |
| Мин. номинал | ~5 USDT | 10 USDT |
| Символ | `BTC-USDT` | `BTC` + целочисленный asset index |
| Источник баланса | `marginSummary.accountValue` | `spotClearinghouseState`, если счёт unified |

Драйвер BingX не тронут относительно версии, проверенной в реальной торговле.
Драйвер Hyperliquid вынесен в отдельный модуль намеренно: правка работающего
кода BingX под чужой протокол поставила бы под риск проверенный путь.

---

## 2. Где лежат ключи

У каждой биржи **свой** зашифрованный файл в каталоге данных:

| Файл | Содержимое |
|---|---|
| `bx_secrets.enc` + `bx_secret.key` | BingX: api key, secret, фонд-пароль, настройки оповещений |
| `hl_secrets.enc` + `hl_secret.key` | Hyperliquid: адрес мастер-аккаунта, приватный ключ агента, среда |

Файлы раздельные намеренно: утечка одного не раскрывает вторую биржу. Оба
шифруются Fernet, мастер-ключи создаются с правами `0600` при первом обращении.

Креды Telegram и e-mail — **общие**: они хранятся в BingX-файле независимо от
того, какая биржа активна, потому что оповещение есть оповещение.

---

## 3. Настройка ключей Hyperliquid (частая ловушка)

Торговля на Hyperliquid идёт **не** приватным ключом аккаунта, а через
**API-кошелёк** (agent wallet):

1. Открой `https://app.hyperliquid.xyz/API`.
2. Создай **API wallet / agent** и скопируй выданный приватный ключ.
3. В приложении: **Настройки торговли → Биржа = Hyperliquid**.
4. Вставь:
   - **Адрес мастер-аккаунта** — твой основной аккаунт (`0x…`), на котором лежат средства;
   - **Приватный ключ агента** — ключ из шага 2;
   - **Среда** — Mainnet или Testnet.
5. Нажми **Проверить подключение**. Это только чтение, ордера не отправляются.

> ⚠️ **Классическая ошибка:** вставить адрес *агента* вместо адреса мастер-аккаунта.
> API вернёт пустой счёт: ни баланса, ни позиций, ни ошибки. Если «Проверить
> подключение» сообщает о пустом счёте — почти всегда причина в этом.

Приватный ключ никогда не логируется и не показывается в интерфейсе — только маска.

---

## 4. Установка SDK Hyperliquid

Драйверу нужен дополнительный набор зависимостей. Базовое приложение работает
без него; тем, кто торгует только на BingX, он не нужен.

```bash
pip install -r requirements-hl.txt
```

Пока он не установлен, попытка выставить ордер на HL завершается понятной
ошибкой с просьбой установить пакет — остальное приложение продолжает работать.

---

## 5. Переключение биржи

В приложении: **💹 Настройки торговли → Биржа** → выбрать бэкенд → **Сохранить**.

### Что происходит при переключении

- Выбранный драйвер становится активным сразу, перезапуск не нужен.
- Панель ключей меняется на выбранную биржу.
- Если **реальная торговля ВЫКЛЮЧЕНА**, переключение применяется молча.

### Если реальная торговля ВКЛЮЧЕНА

Переключение требует явного подтверждения, и приложение объясняет почему:

> **Закрой все позиции на текущей бирже перед сменой: позиции на неактивной
> бирже приложение не отслеживает.**

Это не формальность. Приложение следит за позициями только на активной бирже.
Позиция, оставленная на другой, продолжает жить на бирже, но журнал, карточка
баланса и логика сигналов её больше не видят. Никто её за тебя не закроет.

**Правильный порядок действий:**

1. Закрой все открытые позиции на текущей бирже (в приложении или на самой бирже).
2. Убедись, что список позиций пуст.
3. Переключи биржу.
4. Проверь баланс и позиции в **Настройках торговли**.

---

## 6. Что сохраняется, а что нет

| | При переключении |
|---|---|
| Журнал сделок (история) | Остаётся — он считается по ценовым данным, а не по бирже |
| Параметры стратегий | Остаются |
| Вебхуки и оповещения | Остаются, общие для обеих |
| Список торгуемых тикеров | Остаётся, но символы пересчитываются под новый бэкенд |
| Карточка баланса и PnL | Показывает **новую** биржу; история прежней не смешивается |
| Открытые позиции | **Не переносятся, не закрываются, не отслеживаются** |

PnL считается по каждой бирже отдельно, из её собственной истории income.
Суммировать их нельзя: разные модели комиссий и разное расписание фандинга
сделали бы итог бессмысленным.

---

## 7. Маппинг символов

Большинство тикеров совпадают, но не все:

- **PEPE** на Hyperliquid — это `kPEPE` (цена и размер ×1000). Драйвер
  пересчитывает это внутри; ты по-прежнему вводишь `PEPE`.
- **GRAM** на Hyperliquid — `GRAM`, на BingX — `GRAMTON`.
- Токенизированные активы (например, золото как XAUT) есть в swap-листинге
  BingX, но перпа на Hyperliquid у них **нет** — такой тикер торгуется только на BingX.

Если символа нет на активной бирже, выставление ордера падает с ошибкой, в
которой назван символ. Молча ничего не отправляется.

---

## 8. Откат

Чтобы вернуться на прежнюю биржу:

1. Закрой позиции на текущей.
2. Переключись обратно.
3. Сохрани.

Ключи прежней биржи никуда не удалялись, вводить их заново не нужно. Если нужно
их убрать — кнопка **Удалить ключи** чистит ключи **активной** биржи, и только её.
